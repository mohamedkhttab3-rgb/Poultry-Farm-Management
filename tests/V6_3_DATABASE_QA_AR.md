# اختبارات الحفظ والاستعادة V6.3

- **48/48**: اختبارات انحدار V6.2 داخل Chromium مع تخزين محاكى لجلسة الاختبار. تشمل إدخال البيانات والحسابات والشاشات والفلاتر وExcel والاستيراد والنسخة الكاملة.
- **8/8**: اختبار المتصفح الجديد لتنسيق JSON الجديد، توافق V5.7، رفض نسخة معدلة، رفض الحفظ عند فشل التخزين، ظهور التنبيه، عدم الكتابة فوق النسخة السابقة، وظهور عناصر واجهة الاستعادة. **ملحوظة**: اختبار بصمة التحقق داخل جلسة `about:blank` يستخدم دالة اختبار بديلة، بينما اختبار SHA-256 الفعلي تم في Node.
- **Node** (`tests/test_v63_storage.cjs`): كتابة وتحقق، بصمة SHA-256 حقيقية من WebCrypto، فصل نسخ المستخدمين، منع التكرار، رفض أرشيف متلاعب به، والتعامل مع فشل كتابة أساسي. يستخدم محاكاة لذاكرة IndexedDB وليس قاعدة المتصفح الأصلية.
- **Static**: فحوص JavaScript وZIP وتأكيد عدم حذف ملفات V6.2.

### ما لم يتم اختباره نهائيًا

- استمرارية IndexedDB بعد غلق Chrome وإعادة فتح ملف `file://` على Windows، وQuota التخزين الحقيقي للجهاز.
- الاتصال بخادم Supabase حقيقي أو قواعد RLS أو المزامنة المتزامنة بين أكثر من جهاز.
- بيانات المستخدم الحقيقية؛ كل الاختبارات تمت على بيانات QA مولدة.

**الاختبار اليدوي المقترح:** بعد حفظ نسخة JSON من V6.2، افتح V6.3، أضف مزرعة تجريبية، حدّث الصفحة وتأكد من بقائها. من الإعدادات احفظ لقطة محلية، صدّر JSON، وأعد استيراده في وضع الدمج، ثم راجع سجلات الدورات التاريخية و`standardSnapshot` قبل الاعتماد على النسخة.
